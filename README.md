# Spendly All

PayPay・銀行口座・デビットカード・クレジットカードの明細CSVをまとめて読み込み、家計の支出と収支を集計・可視化するブラウザアプリです。
PayPayだけを分析する [Spendly](https://github.com/xenepic/spendly) から派生しました。

CSVの解析・集計・保存はすべてブラウザ内（IndexedDB）で行い、取引データは外部へ送信しません（本番ビルドはCSPで同一オリジン以外への通信を遮断）。
Vercel Web Analytics（`@vercel/analytics`）はページビューのみを送信し、取引データは含みません。

## 実行

```bash
npm install
npm run dev        # 開発サーバー http://localhost:5174（Spendly の 5173 と同時に起動できる）
npm run build      # 型チェック + 本番ビルド（dist/）
npm test           # ユニット/統合テスト（Vitest + fake-indexeddb）
```

IndexedDB のDB名（`spendly-all`）と画面設定の保存キー（`spendly-all:ui:`）は Spendly と別にしているので、同じオリジンで動かしてもデータは混ざりません。

## 対応する明細

形式はファイルの内容から自動判定します（複数ファイルを一度に選択可）。文字コードは UTF-8（BOM有無）・UTF-16・Shift_JIS を自動判定します。

| 明細 | 判定 | 重複判定キー | 備考 |
|---|---|---|---|
| PayPay 公式形式（13列） | 1行目に `取引日` `取引内容` | 取引番号 + 取引内容 + 入出金方向 | |
| PayPay 旧形式（ヘッダーなし6列） | 6列かつ4列目が `YYYY年M月D日` | 行内容のハッシュ + 出現順 | |
| 銀行の普通預金（`日付,お取引内容,お引出し,お預入れ,残高`） | ヘッダー | 日付・内容・金額・残高のハッシュ + 出現順 | 残高を含むので期間が重なっても重複しない |
| イオンデビット（拡張機能 [debit](../debit) の出力） | ヘッダーが仕様と一致 | 取引番号 | 未確定・有効性確認の行は取り込まない |
| セゾンカード | 1行目が `カード名称` | カード・利用日・店名・金額・支払区分 + 出現順 | カード名ごとに別の支払い元。支払日・請求額を明細から読む |
| 三井住友カード（Vpass の `YYYYMM.csv`） | 1行目に `****` を含むカード番号 | カード・利用日・店名・金額・支払回数 + 出現順 | 支払月はファイル名（なければ最後の利用月の翌月）、請求額は合計行。1行目の氏名・カード番号は保存しない |

- カード・デビットの店名は NFKC で半角カナを全角にし、カナの間の `-` を長音 `ー` に、末尾の空白埋めを除いて扱います（`ﾕ-ﾈｸｽﾄｻ-ﾋﾞｽ` → `ユーネクストサービス`）。元の値は `raw` にそのまま残します。
- 分割払いは毎月の明細に出てきますが、今回の回数を重複判定に含めないので、利用日に総額で1件として計上します。

## 二重計上の防止（振替）

銀行口座からは PayPay へのチャージ・デビットの利用・カードの引落が出ていきますが、その内訳は各明細にあります。
そのまま数えると二重計上になるため、銀行の出金を次のように扱います（`src/lib/accounts.ts`・`src/lib/enrich.ts`）。

| 銀行の取引内容 | 内訳の明細 | 内訳がある場合 | 内訳がない場合 |
|---|---|---|---|
| RS PAYPAY / RS ペイペイ | PayPay | その月の PayPay の明細があれば **振替** | 支出「PayPay（チャージ）」 |
| JCBデビットカード | イオンデビット | その月（ご利用分）の明細があれば **振替** | 支出「イオンデビット（内訳なし）」 |
| セゾン / ミツイスミトモカード | 各カード | 請求額と引落額が一致する請求があれば **振替** | 支出「○○カード（内訳なし）」 |
| 楽天カード・イオンフィナンシャルなど | （未対応） | — | 支出「○○カード（内訳なし）」 |

内訳がない期間の引落は支出として残るので、明細をそろえていない月でも支出の総額は欠けません。判定は表示のたびに元データから計算し直すため、あとから明細を追加すると自動で振替に変わります。
「明細・データ」画面では、カードの請求額と銀行の引落を照合した結果（一致／不一致／銀行明細なし）を確認できます。

デビットの交通系IC（モバイルICOCAなど）へのチャージは、ICの利用明細を取り込まないため支出（交通）として数えます。PayPay へのチャージだけを振替にします。

## 取引種別

| 種別 | 支出集計 | 主な判定 |
|---|---|---|
| 支払い | ✅ 含む | PayPay の支払い・請求書払い、カード・デビットの利用、銀行の口座振替（家賃・年金・携帯料金など）、内訳のない引落 |
| 振替 | 含まない | 内訳の明細がある銀行の引落・チャージ、PayPay からの出金 |
| 投資 | 含まない | ポイント運用、カードの投信積立（`証券` `投信` `積立`）、確定拠出年金の掛金 |
| 収入 | 含まない（収支に使う） | 銀行の入金（給与・振込・利息） |
| 現金（ATM） | 含まない | ATM での引き出し・預け入れ |
| チャージ・送金・受け取り・返金・ポイント・出金 | 含まない | PayPay（Spendly と同じ） |
| 要確認 | 含まない | 判定できないもの（銀行の Web即時決済など）。取引一覧で手動設定 |

## 画面

- **ダッシュボード**: 月の集計カード、カテゴリ別、月別推移、**支払い元別支出**、店舗別、前月比較
- **詳細分析**: カテゴリ・金額帯・店舗・曜日・月別推移、**月別収支**（収入 − 支出）
- **取引一覧**: 期間・種別・カテゴリ・店舗・**支払い元**・金額帯で絞り込み。元データの表示時に、振替かどうかの理由も表示
- **店舗・カテゴリ**: 店舗のカテゴリ設定・一括設定・ルール（Spendly と同じ）
- **明細・データ**: 取り込み、取引種別の内訳、**カードの請求と銀行の引落の照合**、バックアップ（Spendly のバックアップも読み込み可）

「固定費を含める」スイッチをオフにすると、税金・公共料金・住居・通信をカテゴリ別などの内訳から除きます（集計カードと月別収支は常に含む）。

## カテゴリ

スーパー・食品／ドラッグストア・医療／日用品／交通・旅行／外食／趣味・娯楽／コンビニ／ショッピング／税金・公共料金／住居／通信＋その他・未分類。
先頭8色は Spendly と同じ検証済みの配色です。追加した住居・通信は固定費として目立たないくすんだ色にしています（色覚多様性の検証は未実施）。

## データ設計（IndexedDB / Dexie）

| テーブル | 内容 |
|---|---|
| `transactions` | 明細由来の取引。`accountId` で支払い元、`raw` に元の行を保持。金額は正の整数（円）+ `direction` |
| `accounts` | 支払い元（PayPay・銀行口座・デビット・カードごと）。明細から自動登録 |
| `statements` | カードの請求（支払月・請求額）。振替の判定と照合に使う |
| `merchants` / `merchantRules` / `categories` / `txOverrides` / `importHistories` | Spendly と同じ |

## 構成

```
src/lib/csv/index.ts        形式の判定と振り分け、種別の再判定
src/lib/csv/parsePayPay.ts  PayPay（公式・旧形式）
src/lib/csv/parseBank.ts    銀行の普通預金
src/lib/csv/parseDebit.ts   イオンデビット
src/lib/csv/parseCards.ts   セゾンカード・三井住友カード
src/lib/accounts.ts         支払い元・振替の対応（内訳の明細の有無）
src/lib/enrich.ts           分類情報と振替の判定を付加
src/lib/reconcile.ts        カードの請求と銀行の引落の照合
src/lib/analytics.ts        集計（月次・カテゴリ・店舗・支払い元・収支など）
```

テストの明細データ（`tests/fixtures/`）はすべて架空です。実際の明細CSVはコミットしないでください（`.gitignore` で `*.csv` を除外）。
